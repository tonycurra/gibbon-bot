arm

One RoArm-M3 Pro. ESP32 on the HAT talks Feetech at 1 Mbps. USB and BLE are the same text pipe. The console is the brain; the chip clamps and talks to the bus. No IMU, no HAT current chip, no fake sensors.

3. what we can read

Only sensors are inside each Feetech ST32xx. Present block at register 56 (15 bytes). USB does not power the motors — pack off → all miss.

fieldwhatwhen tq=0 (you turn by hand)
posmagnetic encoder 0–4095, wrapsthis is what moves
speedfrom that encoderusually 0 unless you spin fast
loadinner PID effort, not a torque cellalways 0
curwinding current estimate, mA0
movingflag: motor thinks it is tracking a goal0 — not a “I touched it” bit
tqtorque enable0 = free / backdrive
v, temppack at this servo, case °Clive if pack on

So: backdrive → watch pos. Commanded hold/fight → watch load (and cur if it ever leaves 0).

4. servo / wheel / step

Each motor has a mode register (33) in EEPROM. We almost always stay in servo.

modeyou commandinner loopuse here
servo (0)goal position + speed + accposition PID in the servodefault. yaw, pitch, elbow, wrist, hand
wheel (1)signed speedspeed closed-looptwist unwrap / jog only. EEPROM. always restore servo
step / multi-looprelative stepsposition, lost on power-offavoid

There is no torque-control mode. tq=1 means “hold / follow the goal.” It is not a newton-metre setpoint. We do not PWM the HAT ourselves — the servo MCU does the phase drive.

5. how we command

  1. Laptop/console sends a text line (USB or BLE).
  2. ESP32 clamps (walls, hop, pack ≥ 10.5 V) then WritePos on the bus: goal pos, speed (default 300 steps/s), acc (default 20).
  3. The servo tracks that goal with its own loop. We poll get (present @56).

Not a host PWM. Not a host PID writing position from error — that would fight the servo PID. Smoothness today = slow speed + acc, later maybe many small goals (trapezoid) still in servo mode.

6. PID — whose loop?

Classic: error = goal − measured. Effort from P (∝ error), I (sum of error), D (rate of error).

  • Inside the servo — already running in servo mode. Kp/Kd/Ki in EEPROM (who). We do not retune first.
  • Chip — supervisor: clamp, voltage, ESTOP on load/cur/miss while twist is in wheel.
  • Host — unwrap, pair 12+13, later FK. Cadence ~ USB, not kHz.

What we set without touching inner gains: goal, max speed, acc, tq on/off. Load is the effort the inner loop is applying — useful as a contact proxy while tq=1.

A laptop PID on top of the servo PID is worse than either alone. Wheel + outer P (command speed from pos error) is only a maybe for twist unwrap.

7. shoulder pitch 12+13

One joint, two motors, physically stuck together. Move the upper arm by hand and watch both positions. Console actuate on that page sends the same op to both IDs. If they fight, STOP. Firmware does not SyncWrite yet — two packets, same sitting.

8. walls and calibrate

Find the wall by hand, tq off. Mark min / max / home on calibrate from live pos. Commanded moves are a check inside that band, not a way to find it. Hand is already walled (open 609, close 2088). Twist walls known; do not command twist until chip ESTOP is flashed.

EEPROM amin/amax on the chip are often 0–4095 (no wall). Our walls live on the host + firmware clamps for hand/twist.

9. stop

  • Header STOP / Escape = estop (all tq=0, twist back to servo).
  • No move on boot.
  • Do not command a joint with no wall.
  • Never jog 12 or 13 alone.
